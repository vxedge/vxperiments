# AGENTS.md — vxedge/vxperiments

The vxedge experiment catalogue: `vxp/1` packages, frozen results, and the checks that tie each
published verdict to its package. Master spec: `../docs/ARCHITECTURE.md` §6.0 (the workspace
documents; typed intent and the package descriptor in §6.0.3; lock, packed form and digest in
§6.0.7), §12 (methodology, metrics) and §13 (reproducibility). Match the schemas exactly; vxedge
validates against nothing else.

## What lands here

- `experiments/<folder>/`: one `vxp/1` package per experiment. `vxp.yaml` names it, `main.yaml`
  holds the experiment (typed intent, measurements, metrics, criteria, campaign and profiles),
  `vehicle.yaml` and `parts.yaml` the system under test and its software, `vxp.lock` the digest
  of every file. A package carries no campaign runner and no verdict code: vxedge runs its
  campaign and judges its criteria. `tools/` holds only what its own steps need.
- `catalog.yaml`: generated by `scripts/packages.py catalog`, never edited by hand.
- `results/`: frozen summaries, frozen campaign records (`<exp>/campaign.json`) and gate runs,
  as committed text. Run archives are not committed; the published ones are the Zenodo record
  (10.5281/zenodo.23804197; version 2026-11-v2 is 10.5281/zenodo.24192950, mirrored by the
  vxedge/vxarchives release `archives-2026-11-v2`).
- `scripts/`: the catalogue, verdict parity (`verdict-parity.sh`, `parity/`), `frozen-checks.py`,
  the scenario proof and release notes.
- `notebooks/`: exp-010's H2 check only (`notebooks/README.md`). It goes when exp-010 has run live
  as a package; add nothing else here.
- `vehicles/`, `scenarios/`: shared and reference vehicles, and the reference scenario.

## Rules

- **A changed package needs a new version.** Every file in a package folder counts toward its
  digest, README included, and published results and archives cite package digests. After any
  change in a folder: bump `version` in its `vxp.yaml` (PATCH when only docs or packaging
  change), run `vxedge pkg lock` in it, regenerate `catalog.yaml` with `scripts/packages.py
  catalog`, and add a `CHANGELOG.md` line. CI refuses a package that keeps a released version
  with a different digest.
- **Frozen data is never edited.** Files under `results/` that a summary, a campaign record or a
  parity row reads stay as published. A README there may get a corrected link; its account stays.
  Links to the removed runners and notebooks point at the `v0.2.1` tag.
- **Verdicts come from vxedge.** A package's criteria, judged by `vxedge campaign verdict` or
  `vxedge results verdict`, give its verdict. `scripts/verdict-parity.sh --fetch` must keep giving
  every published verdict.
- **Re-freezing a result updates `docs/FACTS.md` in the same change set.** That file is the
  registry every published number is quoted from (website, READMEs, `RESULTS.md`); a summary that
  moved without its registry row leaves the public numbers stale. The website's figure build
  refuses to draw a CSV that disagrees with `FACTS.md`.
- One experiment = one hypothesis focus. Name and describe it accordingly (e.g. exp-001 → H1).
- **Work items are tracked on the maintainers' internal board; the public record of changes is
  `CHANGELOG.md`.** This repo holds what exists and is shipped, not plans or open work.
- **The CI validator is a pinned release.** CI runs the released `vxedge` x86_64 binary named in
  `ci/vxedge-release.txt` (`version=` and `sha256=`), not a build of vxedge `main`. It checks the
  archive's sha256 against that file and verifies its build provenance with
  `gh attestation verify`. To bump the validator, change both lines in that file in one PR (take
  the hash from the release's `SHA256SUMS`); that PR's CI run is the check that every package
  still validates, plans and gives its published verdicts under the new version.

## Checks before a PR

With `VXEDGE` set to the pinned release, from the repository root:

```bash
for p in $(scripts/packages.py list); do "$VXEDGE" --chdir "$p" pkg validate; done
scripts/packages.py catalog --check --base <(git show "$(git describe --tags --abbrev=0)":catalog.yaml)
scripts/verdict-parity.sh --fetch
```

`campaign plan` for every profile needs a vxedged; CI runs one unprivileged.
