## Files

| File | `kind` | What it owns |
|---|---|---|
| `exp-010.vxp` | — | identity, version, entry point, host requirements |
| `main.yaml` | `experiment` | the test: slices, traffic, method, telemetry |
| `vehicle.yaml` | `vehicle` | the system under test: composition, links, channels |
| `parts.yaml` | `baseline` | which software, by ref + digest |

Every file declares its `kind` and `id`. Nothing references anything by path, so you
can rename these files freely. Add a file, it joins the experiment; delete one you do
not need. There is no `road` file here because this template uses synthetic traffic
and has no world to model.

## What to change first

1. **The load** — `traffic_profiles` in `main.yaml`.
2. **The isolation mechanism** — `network.slices[].mode`. Switching `vlan` to
`s-nssai` is the whole difference between H1 and H2, over an unchanged vehicle.
3. **The vehicle** — `composition` and `links` in `vehicle.yaml`.
Device ids (`zonefl`, `hpc1`, `gw1`) name hardware; function ids (`adas`, `percept`)
            name software, and are what `parts.yaml` targets.
4. **The software** — `parts.yaml`. `target_ids` takes one id or a list.

## Sharing it

`vxedge experiment publish` refuses while any local ref (`./images/...`) is still
unpublished: a workspace handed to someone else with a path from your disk in it is
broken for them by construction. Publish those parts first, and the references are
rewritten to digests in place.
