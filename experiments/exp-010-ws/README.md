# exp-010

## The package

This folder is the `vxp/1` package `vxedge/exp-010`, version 0.2.1 (`vxp.yaml`). Its catalogue
alias is `exp-010`. `vxp.lock` records the digest of every file it holds.

`main.yaml` holds the experiment and what used to live in
[`scripts/run.sh`](https://github.com/vxedge/vxperiments/blob/v0.2.1/experiments/exp-010-ws/scripts/run.sh) and
[`../../notebooks/analyze_exp010.py`](../../notebooks/analyze_exp010.py):

| What | Where it was | Where it is |
|---|---|---|
| Load sweep 0, 100, 250, 400, 600 Mbit/s | `LOADS_MBPS` in `run.sh` | `campaign.sweep`, through `load_mbps`, which binds `traffic_profiles[infotainment-load].bandwidth_mbps` |
| 5 repetitions, 10 s of load, then a 60 s probe window | `REPS`, `WARMUP_S`, `PROBE_S` in `run.sh` | `campaign.repetitions`, `warmup_s`, `duration_s`, and the `repro` profile |
| The probe at 1000 pps on the `adas` slice's UE | the `adas-probe` traffic profile | `measurements.ctl-rtt`, through `probe_pps` |
| H2: p99 growth from 0 to 600 Mbit/s within 1.10x of exp-001's | `H2_TOLERANCE` and exp-001's summary in the notebook | `hypothesis`, `metrics`, `references.vlan` and `criteria` |

The probe's end is the `adas` slice's UE. Its address is its PDU session, which the 5G core
assigns at `up`, so the vehicle's link pins none: vxedge 0.20.0 learns it when the measurement
starts, runs the reflector in the UE, and sends from the data-network side through the core, the
path `run.sh`'s probe took.

H2's other arm is exp-001's frozen VLAN campaign, which is not rerun. `../../results/exp-001/campaign.json`
records it; its archives are the published ones (Zenodo `exp-001.tgz`, unpacked into
`../../results/exp-001/`). Run it through vxAPI, from inside this folder:

```bash
vxedge campaign plan --profile repro                                 # the 25 trials; touches nothing
vxedge campaign start --profile repro --reference-workspace ../..    # one archive per trial, then H2's verdict
```

The `quick` profile checks the pipeline only and is never reported. It runs one repetition of the
five loads with `run.sh --quick`'s 3 s and 12 s windows; `run.sh --quick` ran two loads.

The published exp-010 archives hold only each point's probe summary, never samples, so verdict
parity cannot check H2 from them. Checked instead: its `rhs` (exp-001's growth) reads 0.91x from
the frozen record, as the notebook's 0.91x.

The package has not run live: its 5G core and RAN images are not yet published as parts or pinned
in `vxp.lock`. Until it has, the published H2 verdict is checked by
[`../../notebooks/analyze_exp010.py`](../../notebooks/analyze_exp010.py), which CI runs against the
published archives ([`../../notebooks/README.md`](../../notebooks/README.md)).

Generated by `vxedge experiment new --template slicing`. To bring the vehicle up without a
campaign, from inside this folder:

```bash
vxedge experiment validate    # every cross-file check and model invariant; no daemon
vxedge experiment up          # gateway + zones; does NOT start traffic
vxedge experiment down
```

## Before the package

The published exp-010 campaigns were run by the bash runner
[`scripts/run.sh`](https://github.com/vxedge/vxperiments/blob/v0.2.1/experiments/exp-010-ws/scripts/run.sh),
as the user's own account: it brought up the 5G core with rootless Podman and used `sudo` only for
the host steps that needed it. This workspace replaced the §6.1 manifest
[`retired-6.1/exp-010.yaml`](https://github.com/vxedge/vxperiments/blob/v0.2.1/experiments/retired-6.1/exp-010.yaml).
vxperiments 0.2.1 is the last release that has either.

## Files

| File | `kind` | What it owns |
|---|---|---|
| `vxp.yaml` | — | identity, version, entry point, host requirements |
| `main.yaml` | `experiment` | the test: slices, traffic, measurement, typed intent, campaign |
| `vehicle.yaml` | `vehicle` | the system under test: zones, devices, functions, links, channels |
| `parts.yaml` | `baseline` | which software, by ref + digest |

Every file declares its `kind` and `id`. Nothing references anything by path, so you
can rename these files freely. Add a file, it joins the experiment; delete one you do
not need. There is no `road` file here because this template uses synthetic traffic
and has no world to model.

## What to change first

1. **The load** — `traffic_profiles` in `main.yaml`.
2. **The isolation mechanism** — `network.slices[].mode`. Switching `vlan` to
`s-nssai` is the whole difference between H1 and H2, over an unchanged vehicle.
3. **The vehicle** — `devices`, `functions` and `links` in `vehicle.yaml`.
Device ids (`zonefl`, `hpc1`, `gw1`) name hardware; function ids (`adas`, `percept`)
            name software, and are what `parts.yaml` targets.
4. **The software** — `parts.yaml`. `target_ids` takes one id or a list.

## Sharing it

`vxedge pkg pack` packs this folder into one `.vxp` file with its package digest, and refuses
when `vxp.lock` does not match. A vxperiments release pushes the packed package to
`ghcr.io/vxedge/experiments/exp-010` under its version (`../../catalog.yaml`).
